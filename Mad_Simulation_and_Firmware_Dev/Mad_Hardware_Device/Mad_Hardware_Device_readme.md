MAD Hardware Device — FPGA PCIe Endpoint
Overview
The MAD Hardware Device project implements a custom PCI Express endpoint in aXilinx Kintex UltraScale+ FPGA.
It complements a Linux simulated-device environment developed for stream and block device driver testing.

The engineering objective is to implement a physical PCIe device with a programming model corresponding to
the simulated device, as a prototype of the developing PCIe endpoint driver(s) without real hardware and 
transitioning to hardware when available as implemented in FPGA.

This repository is an engineering reference and development project, not a production-qualified device.

Architecture
The design integrates the AMD/Xilinx PCIe endpoint IP with custom RTL implementing device registers,
 data buffers, and PCIe transaction handling.
- BAR0: Memory-mapped device control and status registers.
- BAR2 and BAR4: Data-buffer interfaces for device transfers.
- PCIe request/completion handling: Custom logic interfaces with the PCIe core's CQ/CC paths.
- Debug and verification: Vivado simulation, Integrated Logic Analyzer (ILA) instrumentation,
                          and Linux host diagnostics.
The implementation uses the PCIe core's CQ, CC, RQ, and RC AXI4-Stream interface conventions.
The custom logic has been streamlined around a 128-bit datapath.

Development and verification status
Development has included PCIe link bring-up and enumeration on Linux, BAR register access, 
host/device buffer testing, and PCIe completion-path debugging using Vivado ILA captures.

Physical-hardware demonstrations have been achieved for full end-to-end validation of stream-io transfers,
DMA scatter-gather transfers, MSI interrupt generation and processing, with a comprehensive test suite.
 
Rebuilding and portability
The reference target is the KCU116 board with Vivado 2023.2.
A migration to another board would require review of FPGA part selection, PCIe IP configuration,
transceiver connectivity, reference clocks, reset, XDC constraints, and available resources.

Much of the device-specific RTL may be reusable on compatible AMD/Xilinx FPGA targets, 
but board portability has not yet been demonstrated.

To reproduce the project, inspect the tracked Vivado project sources and constraints, ensure the 
required AMD/Xilinx tools and IP are available, and regenerate excluded build products locally.
Exact reproducibility on a clean machine remains to be verified.

Intended use
This project illustrates engineering techniques in:
- Linux kernel device-driver and FPGA endpoint development.
- PCIe BAR, register, and completion-path integration.
- Hardware simulation prior to physical hardware availability.
- FPGA and Linux host-side debugging.
- Embedded Linux integration and hardware/software verification.
